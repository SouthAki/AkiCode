# Proposal: MCP App 架构画布与插件自我迭代

## 背景

插件目前通过独立 Skills 和本地 stdio MCP 工具提供仓库理解、规划与 Diff Review。用户看不到这些能力之间的关系，也没有专门流程根据实际使用中暴露的问题持续改进插件。

## 目标

- 增加一个 MCP Apps 架构画布，直观展示插件模块、能力和工作流关系。
- 允许用户选中画布中的能力并描述调整；UI 将明确的需求发送回当前对话，由 `$vibe-code` 按既有工作流实施。
- 增加独立 `vibe-evolve` Skill，按证据诊断问题，提出可审查的改进并通过规划、实施、复核、验证闭环迭代。

## 范围

- 第一方 MCP App 资源、只读架构工具和可缩放/拖动画布。
- 第一方自我诊断与迭代 Skill。
- MCP/UI 构建与插件打包更新。
- 更新 README、MCP 文档和设计参考中的架构图与边界。

## 非目标

- UI 直接写入源码或自动执行未授权的代码修改。
- 静默采集遥测、会话内容或网络数据。
- 复制 Superpowers 或 MCP Apps 参考项目的源码、提示词、资产或实现结构。
- 改变现有 repository、plan、review 工具的输入输出契约。

## 成功条件

- 调用架构工具时返回结构化能力图，并将 `text/html;profile=mcp-app` UI 资源关联到该工具。
- 画布支持平移、缩放、选择能力、编辑优化描述，并通过 MCP Apps bridge 发送包含能力上下文的跟进消息。
- 即使 MCP host 不渲染 UI，架构工具仍返回可读结构化内容，现有工具和 Skills 仍可工作。
- `vibe-evolve` 明确区分证据、推断和待确认事项；未经用户授权不修改代码。
- 构建、源码大小检查和插件打包使用新的、不会覆盖已有用户文件的产物目录。
